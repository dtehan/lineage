# Requirements Archive: v3.0 Wildcard Expansion & Graph Enhancements

**Defined:** 2026-02-18
**Shipped:** 2026-02-19
**Core Value:** Enable accurate impact analysis for database changes by visualizing complete column-level lineage across Teradata databases

## v3.0 Requirements — All Shipped

### Core Wildcard Expansion

- [x] **CORE-01**: System expands simple `SELECT *` to actual column names using table metadata — *Shipped in Phase 7 via WildcardResolver.resolve_star()*
- [x] **CORE-02**: System matches columns by ordinal position (1st→1st, 2nd→2nd) for `INSERT INTO...SELECT *` statements — *Shipped in Phase 7-02, TeradataSQLParser*
- [x] **CORE-03**: System derives target column names from source for `CREATE TABLE AS SELECT *` statements — *Shipped in Phase 7-02*
- [x] **CORE-04**: System batch-queries and caches table metadata to prevent N+1 query performance trap — *Shipped in Phase 7-01, WildcardResolver.warm_cache() batches 100 tables per query*
- [x] **CORE-05**: System assigns confidence score 0.70 to wildcard-expanded lineage (vs 0.95 for explicit columns) — *Shipped in Phase 7-02*
- [x] **CORE-06**: System handles case-insensitive Teradata identifier matching during metadata resolution — *Shipped in Phase 7-01, uppercase normalization for unquoted identifiers*
- [x] **CORE-07**: System detects and skips multi-table unqualified `SELECT *` with warning (ambiguous table attribution) — *Shipped in Phase 7-02*
- [x] **CORE-08**: System sets CTE/subquery expansion depth limit (5 levels) with cycle detection — *Shipped in Phase 7-02*

### Qualified Wildcards

- [x] **QUAL-01**: System expands qualified wildcards (`SELECT t1.*`) using table alias resolution — *Shipped in Phase 8-01*
- [x] **QUAL-02**: System handles multi-table queries with multiple qualified wildcards (`SELECT t1.*, t2.*`) — *Shipped in Phase 8-01*
- [x] **QUAL-03**: System detects schema evolution (column count changes) and logs warnings — *Shipped in Phase 8-01, WildcardResolver schema evolution detection*
- [x] **QUAL-04**: System logs each wildcard expansion (table, column count, timestamp) for audit trail — *Shipped in Phase 8-01, audit logging on every expansion*
- [x] **QUAL-05**: System continues extraction when individual wildcard expansion fails (graceful degradation) — *Shipped in Phase 7-01 + 8-01, graceful degradation pattern*
- [x] **QUAL-06**: System detects positional ORDER BY references and skips with warning — *Shipped in Phase 8-01*

### View Expansion

- [x] **VIEW-01**: System detects view references in queries (via DBC.TablesV.TableKind) — *Shipped in Phase 9-01*
- [x] **VIEW-02**: System retrieves and parses view definitions from DBC.TablesV.RequestText — *Shipped in Phase 9-01, REPLACE VIEW → CREATE VIEW normalization*
- [x] **VIEW-03**: System recursively expands wildcards in view definitions with depth limit (3 levels) — *Shipped in Phase 9-01, MAX_VIEW_EXPANSION_DEPTH=3*
- [x] **VIEW-04**: System caches expanded view schemas for reuse across queries — *Shipped in Phase 9-01, _column_cache shared with table cache*
- [x] **VIEW-05**: System detects circular view references and logs errors — *Shipped in Phase 9-01*

## v4.0 Requirements

Deferred to future release. Tracked but not in current roadmap.

### BigQuery Compatibility

- **BQRY-01**: System supports `SELECT * EXCEPT (column)` syntax for BigQuery-compatible lineage
- **BQRY-02**: System supports `SELECT * REPLACE (expr AS column)` syntax

### Schema Versioning

- **SCHM-01**: System tracks schema versions with timestamps for historical accuracy
- **SCHM-02**: System reconstructs historical schemas for queries executed in the past
- **SCHM-03**: System flags lineage with schema version mismatches

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Real-time wildcard expansion during query execution | Adds latency to queries; extraction is batch process |
| Auto-fix column mismatches | Guessing creates incorrect lineage; fail fast instead |
| Name-based column matching for INSERT INTO | Violates SQL standard (ordinal position is correct) |
| Cross-database wildcard resolution | Edge case; most queries single-database; adds complexity |
| DBC.ColumnsV metadata source | Returns NULL for view column types; DBC.ColumnsJQV required |
| SELECT * EXCEPT for v3.0 | BigQuery-specific, not Teradata native; defer to v4.0 |
