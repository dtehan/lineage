**Step 1: Understand OL_COLUMN_LINEAGE schema**

`OL_COLUMN_LINEAGE` stores lineage edges with `source_dataset VARCHAR(256)` and `target_dataset VARCHAR(256)` as name strings (NOT foreign keys to OL_DATASET.dataset_id). These names are in the format `database.table` (same format as `OL_DATASET."name"`).

**Step 2: Modify list_datasets in dataset_repository.py**

In the `list_datasets` method (around line 222), modify the inner SELECT to add a `has_lineage` column using a CASE WHEN EXISTS subquery. The `OL_COLUMN_LINEAGE` table stores dataset names as `source_dataset` and `target_dataset` strings. The JOIN must match `TRIM(d."name")` against both columns.

Change the inner SELECT from:
```sql
SELECT
    d.dataset_id,
    d."name" as dataset_name,
    d.namespace_id,
    n.namespace_uri,
    d.description,
    d.source_type,
    d.created_at,
    d.updated_at,
    ROW_NUMBER() OVER (ORDER BY d."name") as rn
FROM OL_DATASET d
JOIN OL_NAMESPACE n ON d.namespace_id = n.namespace_id
WHERE d.namespace_id = ?{extra_where}
```

To:
```sql
SELECT
    d.dataset_id,
    d."name" as dataset_name,
    d.namespace_id,
    n.namespace_uri,
    d.description,
    d.source_type,
    d.created_at,
    d.updated_at,
    CASE
        WHEN EXISTS (
            SELECT 1 FROM OL_COLUMN_LINEAGE cl
            WHERE TRIM(cl.source_dataset) = TRIM(d."name")
               OR TRIM(cl.target_dataset) = TRIM(d."name")
        ) THEN 'Y' ELSE 'N'
    END AS has_lineage,
    ROW_NUMBER() OVER (ORDER BY d."name") as rn
FROM OL_DATASET d
JOIN OL_NAMESPACE n ON d.namespace_id = n.namespace_id
WHERE d.namespace_id = ?{extra_where}
```

Update the outer SELECT to include `has_lineage`:
```sql
SELECT dataset_id, dataset_name, namespace_id, namespace_uri,
       description, source_type, created_at, updated_at, has_lineage
FROM (
    ...
) t
WHERE rn > ? AND rn <= ?
```

Update the row-to-dict mapping to include `hasLineage`:
```python
datasets = [
    {
        "id": self._strip(row[0]) if row[0] else "",
        "name": self._strip(row[1]) if row[1] else "",
        "namespace": self._strip(row[3]) if row[3] else "",
        "description": self._strip(row[4]) if row[4] else "",
        "sourceType": self._strip(row[5]) if row[5] else None,
        "createdAt": self._isoformat(row[6]),

    }

```

Note: `row[8]` is the `has_lineage` column (0-indexed: dataset_id=0, dataset_name=1, namespace_id=2, namespace_uri=3, description=4, source_type=5, created_at=6, updated_at=7, has_lineage=8).

**Step 4: Verify the database name format**

`OL_DATASET."name"` stores dataset names in `database.table` format (e.g., `demo_user.customers`). `OL_COLUMN_LINEAGE.source_dataset` and `target_dataset` store the same format. The TRIM match ensures no trailing spaces from Teradata CHAR padding cause mismatches.

**Performance note:** The EXISTS subquery with TRIM runs per row, bounded by `limit: 500` (Phase 22 decision). Existing indexes `idx_ol_lineage_src_ds (source_dataset)` and `idx_ol_lineage_tgt_ds (target_dataset)` on `OL_COLUMN_LINEAGE` support this query. TRIM may prevent index usage on some Teradata versions — if performance is an issue, this can be optimized later by pre-trimming the stored data. For now, 500 EXISTS checks is acceptable.
