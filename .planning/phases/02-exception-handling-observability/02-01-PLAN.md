  <action>
Create the `lineage-api/exceptions/` package with three files:

**exceptions/base.py:**
- Define `LineageException(Exception)` as the base for all domain exceptions
- Attributes: `message` (str), `status_code` (int, default 500), `details` (dict, default {})
- Method: `to_dict()` returns `{"error": self.message}` (preserving the existing `{"error": string}` response contract exactly). Do NOT include `details` in the dict output -- only `{"error": string}` to match the current API contract.

**exceptions/domain.py:**
- `DatasetNotFoundError(LineageException)`: status_code = 404. This replaces the current `ValueError` pattern used in services for "not found" cases.
- `LineageTraversalError(LineageException)`: status_code = 500. For errors during graph traversal (CTE failures, unexpected data).
- `DatabaseConnectionError(LineageException)`: status_code = 500. Accepts optional `original_error: Exception` parameter to wrap teradatasql exceptions. The `to_dict()` method must NOT expose the original_error to clients.

**exceptions/__init__.py:**
- Re-export all three domain exceptions and `LineageException` for convenient imports: `from exceptions import DatasetNotFoundError`

**utils/__init__.py:**
- Empty file (package marker)

**utils/sanitize.py:**
- Define `sanitize_error_message(message: str) -> str` function
- Strip patterns: password values (key=value or key:value), Bearer tokens, connection strings containing credentials (host:port with password patterns)
- Use compiled regex patterns at module level for performance
- Replace matches with `[REDACTED]`
- Keep sanitization conservative -- only filter clearly sensitive patterns, not general text. Do NOT filter email addresses or SSNs (not relevant to this application).
  </action>
  <verify>
Run from lineage-api directory:
