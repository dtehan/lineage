  <name>Task 1: Create GraphEngine singleton with BFS traversal and blue-green swap</name>
  <files>

  </files>
  <action>
  Create `lineage-api/graph/engine.py` with the following:

  1. Imports: `threading`, `networkx as nx`, `loguru.logger`, `GraphStore` from `graph.store`, `GraphLoader` from `graph.loader`.

  2. Define `class GraphEngine`:
     - `__init__(self)`:
       - `self._store: GraphStore | None = None`
       - `self._lock = threading.RLock()`
       - `self._ready = threading.Event()`
       - `self._loader: GraphLoader | None = None`

     - `initialize(self, connection)`:
       - Creates `self._loader = GraphLoader(connection)`.
       - Starts a daemon background thread `threading.Thread(target=self._warmup, daemon=True, name="graph-warmup")`.
       - Logs: `logger.info("Graph engine: initialization started")`.

     - `_warmup(self)`:
       - Wrapped in try/except. On exception, logs error and does NOT set ready event (engine stays in fallback mode).
       - Calls `graph = self._loader.load()`.
       - Calls `self._swap(graph)`.
       - Sets `self._ready.set()`.
       - Logs success with node/edge counts.

     - `_swap(self, graph: nx.DiGraph)`:
       - Builds `new_store = GraphStore.build(graph)`.
       - Acquires `self._lock` ONLY for the reference swap: `with self._lock: self._store = new_store`.
       - Critical: lock is held only for the single assignment, never during build or traversal.

     - `@property is_ready(self) -> bool`:
       - Returns `self._ready.is_set()`. No lock needed (Event.is_set() is atomic).

     - `traverse_upstream(self, node_id: str, max_depth: int) -> list[dict]`:
       - Acquires lock only to copy reference: `with self._lock: store = self._store`.
       - If `store is None` or `node_id not in store.graph`: return `[]`.
       - Calls `self._bfs_edges(store.graph, node_id, reverse=True, max_depth=max_depth)`.

     - `traverse_downstream(self, node_id: str, max_depth: int) -> list[dict]`:
       - Same pattern but `reverse=False`.

     - `_bfs_edges(self, G: nx.DiGraph, source: str, reverse: bool, max_depth: int) -> list[dict]`:
       - Uses `nx.bfs_edges(G, source=source, reverse=reverse, depth_limit=max_depth)`.
       - For each `(u, v)` yielded:
         - If `reverse=True`: `src_node, tgt_node = v, u` (BFS parent is downstream node when going upstream).
         - If `reverse=False`: `src_node, tgt_node = u, v`.
         - Fetch edge data: `edge_data = G[src_node][tgt_node]`.
         - Split node IDs with `rsplit(".", 1)` to get `(dataset_name, field_name)`.
         - Build result dict matching CTE output format:
           ```python
           {
               "source_dataset": src_dataset,
               "source_field": src_field,
               "target_dataset": tgt_dataset,
               "target_field": tgt_field,
               "transformation_type": edge_data.get("transformation_type", "DIRECT"),
           }
           ```
       - NOTE: This dict intentionally OMITS `source_namespace` and `target_namespace`. These will be resolved by the calling code in LineageService (see Task 2).

     - `@property status(self) -> dict`:
       - Acquires lock to copy reference.
       - If store is None: returns `{"ready": False, "node_count": 0, "edge_count": 0, "last_rebuild_time": None, "memory_bytes": 0}`.
       - Otherwise returns: `{"ready": True, "node_count": store.node_count, "edge_count": store.edge_count, "last_rebuild_time": store.loaded_at, "memory_bytes": store.memory_bytes}`.

  3. At module level, create the singleton: `graph_engine = GraphEngine()`.

  4. Update `lineage-api/graph/__init__.py` to also export `GraphEngine` and `graph_engine`.
  </action>

  **LineageService changes (lineage_service.py):**

  1. Add import at top: `from graph.engine import graph_engine`.

  2. Create a new private method `_resolve_namespace(self, dataset_name: str, namespace_cache: dict) -> str`:
     - If `dataset_name in namespace_cache`: return cached value.
     - Otherwise: `meta = self.dataset_repo.get_dataset_metadata(dataset_name)`.
     - Cache and return `meta["namespace"] if meta else ""`.
     - This resolves the namespace gap between BFS results (no namespace) and CTE results (have namespace).

  3. Create a new private method `_enrich_bfs_results(self, bfs_edges: list[dict]) -> list[dict]`:
     - Purpose: Add `source_namespace` and `target_namespace` fields to BFS result dicts so they match the CTE result format that `_add_lineage_results()` expects.
     - Create a local `namespace_cache = {}`.
     - For each edge dict in `bfs_edges`:
       - `edge["source_namespace"] = self._resolve_namespace(edge["source_dataset"], namespace_cache)`.
       - `edge["target_namespace"] = self._resolve_namespace(edge["target_dataset"], namespace_cache)`.
     - Return the enriched list.
     - NOTE: The namespace_cache avoids N+1 queries — most edges share a small number of distinct datasets.

  4. Modify `get_column_lineage_graph()` — add dual-path routing for upstream and downstream:
     - Before the existing upstream block, check `use_graph = graph_engine.is_ready`.
     - For upstream (inside `if direction in ("upstream", "both")`):
       - If `use_graph`:
         ```python
         bfs_edges = graph_engine.traverse_upstream(
             f"{dataset_name}.{field_name}", max_depth
         )
         upstream_records = self._enrich_bfs_results(bfs_edges)
         ```
       - Else: use existing CTE path (unchanged).
       - Then call `self._add_lineage_results(upstream_records, nodes, edges, source_type_cache)` as before.
     - For downstream: same pattern with `graph_engine.traverse_downstream`.

  5. Modify `get_table_lineage_graph()` — same dual-path pattern:
     - Check `use_graph = graph_engine.is_ready` once before the field loop.
     - Inside the field loop, for upstream and downstream blocks:
       - If `use_graph`: use `graph_engine.traverse_upstream/downstream` + `_enrich_bfs_results`.
       - Else: use existing CTE path.

  6. Do NOT modify `get_database_lineage_graph()` in this plan. Database-level lineage has a different query pattern (batch dataset names, bidirectional CTE). It will continue using the CTE path. This is acceptable — column and table lineage are the performance-critical paths.
