  <files>

  <action>
  Create `lineage-api/tests/test_graph_engine.py` with comprehensive unit tests. Use `unittest` framework (matching existing test pattern in `test_lineage_service.py`). No database connection needed — all tests use in-memory DiGraphs.

  Add `sys.path.insert(0, os.path.join(os.path.dirname(__file__), '..'))` for imports.

  **Helper function: `build_test_graph(edges: list[tuple]) -> nx.DiGraph`**
  - Takes a list of `(source_id, target_id, transformation_type)` tuples.
  - Builds and returns a DiGraph with those edges.

  **Helper function: `edges_to_set(edges: list[dict]) -> set[tuple]`**
  - Converts list of edge dicts to a set of `(source_dataset, source_field, target_dataset, target_field, transformation_type)` tuples.
  - Used for order-independent comparison between BFS and expected results.

  **Test class: `TestGraphStore`** (3 tests)
  - `test_build_creates_valid_snapshot`: Build a GraphStore from a small DiGraph, verify node_count, edge_count, loaded_at > 0, memory_bytes > 0.
  - `test_build_empty_graph`: Build from empty DiGraph, verify node_count=0, edge_count=0.
  - `test_build_measures_memory`: Verify memory_bytes is a positive integer (psutil returns real RSS).

  **Test class: `TestGraphEngine`** (12+ tests)

  Setup: Create a fresh `GraphEngine` instance for each test (do NOT use the module-level singleton to avoid test pollution).

  *Status and readiness tests:*
  - `test_status_when_not_initialized`: Fresh engine returns `{"ready": False, "node_count": 0, ...}`.
  - `test_is_ready_false_before_initialize`: `is_ready` returns False on fresh engine.

  *Traversal with manually set graph (bypass warmup thread for deterministic tests):*
  For traversal tests, directly set `engine._store` to a `GraphStore.build(G)` and `engine._ready.set()` to simulate a warmed engine without needing a real DB connection.

  *Linear chain: A -> B -> C (DIRECT)*
  - `test_upstream_linear_chain`: From C, upstream depth=5 returns edges B->C and A->B.
  - `test_downstream_linear_chain`: From A, downstream depth=5 returns edges A->B and B->C.
  - `test_upstream_depth_limit`: From C, upstream depth=1 returns only B->C (not A->B).
  - `test_downstream_depth_limit`: From A, downstream depth=1 returns only A->B (not B->C).

  *CYCLE5 pattern: A -> B -> C -> D -> E -> A (circular)*
  Build 5-node cycle: `db.t1.col -> db.t2.col -> db.t3.col -> db.t4.col -> db.t5.col -> db.t1.col`.
  - `test_cycle_upstream_does_not_infinite_loop`: From db.t1.col, upstream depth=10 returns edges without hanging. Verify result length <= 5 (cannot have more unique edges than exist in a 5-node cycle). BFS naturally handles cycles (visited set).
  - `test_cycle_downstream_does_not_infinite_loop`: Same from downstream direction.

  *NESTED_DIAMOND pattern: A -> B, A -> C, B -> D, C -> D*
  - `test_diamond_upstream_from_D`: From D, upstream returns all 4 edges (A->B, A->C, B->D, C->D). Verify as a set (order-independent).
  - `test_diamond_downstream_from_A`: From A, downstream returns all 4 edges. Verify as a set.

  *FANOUT10 pattern: A -> B1, A -> B2, ..., A -> B10*
  - `test_fanout_downstream`: From A, downstream depth=1 returns 10 edges. Verify all 10 targets are present.

  *Edge cases:*
  - `test_node_not_in_graph_returns_empty`: Traverse non-existent node returns [].
  - `test_traverse_on_uninitialized_engine_returns_empty`: Fresh engine (no store) returns [] for traverse calls.

  *Result format tests:*
  - `test_result_dict_keys`: Verify each edge dict from traverse has exactly: source_dataset, source_field, target_dataset, target_field, transformation_type.
  - `test_transformation_type_preserved`: Add edges with different transformation types (DIRECT, IDENTITY, AGGREGATION), verify they are preserved in results.

  *Bidirectional traversal test:*
  - `test_bidirectional_traversal`: For a linear chain A->B->C, from B: upstream returns A->B, downstream returns B->C. Combined gives full picture.

  Run: `python -m unittest tests.test_graph_engine -v` from lineage-api/.
