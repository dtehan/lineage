```sql
CAST(s.SQLTextInfo AS VARCHAR(32000)) as query_text,
LENGTH(s.SQLTextInfo) as sql_length,
```

2. Update the `fetch_queries` return to include `sql_length`. The tuples change from 5 elements to 6: `(QueryID, StatementType, query_text, StartTime, DefaultDatabase, sql_length)`.

3. After fetching results, add a warning log for any queries where `sql_length > 32000`:
```python
queries = self.cursor.fetchall()
# Warn about truncated SQL text
truncated_count = sum(1 for q in queries if q[5] and q[5] > 32000)
if truncated_count:
    logger.warning(
        "DBQL truncation: %d of %d queries exceed VARCHAR(32000) limit - "
        "lineage extraction may be incomplete for these queries",
        truncated_count, len(queries)
    )
```

4. In the `extract_lineage` method's processing loop (line 292), update the tuple unpacking to include `sql_length`:


This ensures users see clear warnings in extraction logs when SQL truncation occurs, matching the research recommendation.
