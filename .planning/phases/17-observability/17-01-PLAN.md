  <action>
Create `lineage-api/middleware/timing.py` following the exact pattern of `correlation_id.py`:

1. **`init_timing_middleware(app: Flask)`** function that registers two hooks:
   - `@app.before_request`: Set `g.timing = {}` and `g.request_start = time.perf_counter()`
   - `@app.after_request`: If `g.timing` contains any entries, serialize them into a `Server-Timing` response header using W3C format: `name;dur=X.XX` (2 decimal places to avoid sub-ms rounding to 0.0). Also add a `total;dur=X.XX` metric computed from `g.request_start`. If `g.timing` is empty, do NOT add the header.

2. **`record_timing(name: str, elapsed_ms: float)`** module-level helper:
   - Imports `g` from flask inside the function body (to avoid circular imports and allow calling from service layer)
   - Checks `hasattr(g, 'timing')` before writing — silently no-ops if called outside request context (e.g., background threads)
   - Sets `g.timing[name] = elapsed_ms`

In `python_server.py`:
3. Import `init_timing_middleware` from `middleware.timing`
4. Call `init_timing_middleware(app)` immediately after `init_correlation_id_middleware(app)` (before routes)
5. Add `expose_headers=['Server-Timing']` to the `CORS()` call so the header is readable from JavaScript in cross-origin requests. Update the existing CORS call — do NOT create a second one.

In `graph/engine.py`:
6. Add a `last_rebuild_iso` convenience field to the `status` property. When `store` is not None and `store.loaded_at` is set, format it as ISO 8601 UTC string using `datetime.fromtimestamp(store.loaded_at, tz=timezone.utc).isoformat()`. When store is None, return `null`. Import `datetime` and `timezone` from `datetime` module at the top of the file.

In `routes/graph.py`:
7. No changes needed — it already returns `graph_engine.status` as JSON, so the new `last_rebuild_iso` field will be included automatically.

IMPORTANT: Use `time.perf_counter()` (NOT `time.time()`) for all duration measurements — it is monotonic and high-resolution.
  </action>

In `lineage_service.py`:
1. Add `import time` at the top and `from middleware.timing import record_timing` below existing imports.

2. In `get_column_lineage_graph()`, wrap the BFS and CTE paths with `time.perf_counter()` pairs:
   - **Upstream BFS path** (when `use_graph` is True): time the `graph_engine.traverse_upstream()` call and call `record_timing("bfs_upstream", (time.perf_counter() - t0) * 1000)`. Include the `_enrich_bfs_results` call inside the timed block since it is part of the BFS path cost.
   - **Upstream CTE path** (when `use_graph` is False): time the `self.lineage_repo.get_upstream_lineage()` call and call `record_timing("db_upstream", (time.perf_counter() - t0) * 1000)`.
   - **Downstream BFS path**: Same pattern, record as `"bfs_downstream"`.
   - **Downstream CTE path**: Same pattern, record as `"db_downstream"`.

3. In `get_table_lineage_graph()`, wrap the entire field loop (NOT each individual field) with a single timer:
   - **BFS path total**: time the entire for-field loop when `use_graph` is True, record as `"bfs_total"`.
   - **CTE path total**: time the entire for-field loop when `use_graph` is False, record as `"db_total"`.
   This keeps the Server-Timing header readable (one aggregate metric, not N per-field metrics).

4. In `get_database_lineage_graph()`, wrap the `self.lineage_repo.get_database_lineage()` call with a timer and record as `"db_lineage"`. Database lineage always uses CTE.

Create `lineage-api/tests/test_timing.py`:

   - `test_server_timing_header_absent_when_no_timings`: Same app but test route does NOT call record_timing. Assert `Server-Timing` header is NOT in response headers.
   - `test_server_timing_total_included`: Test route calls `record_timing("foo", 10.0)`. Assert response header contains both `foo;dur=10.00` and `total;dur=` (total should be present and > 0).

7. **TestLineageServiceTiming class** (3 tests):

   - `test_table_lineage_records_aggregate_timing`: Mock appropriate methods, call `get_table_lineage_graph()`, assert `g.timing` contains either `bfs_total` or `db_total` (not per-field keys).
