  <action>
Refactor lineage-api/python_server.py to Application Factory pattern:
- Remove all inline route definitions (the 11 @app.route handlers)
- Remove inline DB_CONFIG and get_db_connection (now in config.py)
- Remove validate_required_credentials (now in config.py)
- Keep CORS configuration
- Create create_app() function that:
  1. Creates Flask app
  2. Configures CORS (same origins as current: localhost:3000, 3001, 3004, 5173)
  3. Creates DB connection via config.get_db_connection()
  4. Instantiates repositories (LineageRepository, DatasetRepository)
  5. Instantiates services (LineageService, DatasetService, ImpactService)
  6. Calls init_services on openlineage_bp
  7. Registers health_bp and openlineage_bp
  8. Returns app
- Keep the if __name__ == "__main__" block but have it call create_app()

The connection lifecycle: For now, create a single connection at app startup and share it across repositories (matching current behavior where get_db_connection() is called per request). The per-request pattern will be preserved by having services create new repository instances per request using Flask's before_request hook, OR by having repositories use get_db_connection() internally. Choose the simpler approach: have repositories call get_db_connection() at method invocation time rather than storing a persistent connection. This way BaseRepository.__init__() takes no args, and each repository method calls get_db_connection() when it needs a cursor. This matches the current per-request connection pattern in python_server.py.
