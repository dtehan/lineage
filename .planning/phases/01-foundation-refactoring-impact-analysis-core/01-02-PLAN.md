Create lineage-api/services/lineage_service.py with class LineageService:
- Constructor: __init__(self, lineage_repo: LineageRepository, dataset_repo: DatasetRepository)
- Methods:
  - get_column_lineage_graph(dataset_id: str, field_name: str, direction: str, max_depth: int) -> dict:
    Replicates the logic from get_openlineage_lineage() (lines 686-925 of python_server.py):
    1. Look up dataset name from dataset_repo
    2. Call lineage_repo.get_upstream_lineage() and/or get_downstream_lineage() based on direction
    3. Build nodes dict and edges list (the node/edge building logic from lines 764-800 and 852-888)
    4. Add root field node if not present
    5. Return {"datasetId": ..., "fieldName": ..., "graph": {"nodes": [...], "edges": [...]}}

  - get_table_lineage_graph(dataset_id: str, direction: str, max_depth: int) -> dict:
    Replicates logic from get_openlineage_table_lineage() (lines 928-1165):
    1. Look up dataset name and namespace
    2. Get all fields for dataset
    3. For each field, call upstream/downstream lineage from repo
    4. Build aggregated nodes and edges
    5. Return {"datasetId": ..., "graph": {"nodes": [...], "edges": [...]}}

  - get_database_lineage_graph(database_name: str, direction: str, max_depth: int) -> dict:
    Replicates logic from get_openlineage_database_lineage() (lines 1172-1443):
    1. Get all datasets in database
    2. Add all field nodes for each dataset
    3. Call lineage_repo.get_database_lineage() with dataset names
    4. Process results, add external nodes with metadata lookups
    5. Return {"databaseName": ..., "direction": ..., "maxDepth": ..., "graph": {"nodes": [...], "edges": [...]}}

  - Helper method _build_node(key, field_name, dataset_name, namespace) -> dict for creating node dicts
  - Helper method _build_edge(source_key, target_key, transformation_type) -> dict for creating edge dicts
  - Helper method _add_lineage_results(records, nodes, edges) to process lineage records into nodes/edges (eliminates duplication between column/table endpoints)

CRITICAL: The node and edge dict shapes MUST exactly match what python_server.py currently produces. Test by comparing JSON outputs.

Create lineage-api/services/impact_service.py with class ImpactService:
- Constructor: __init__(self, lineage_repo: LineageRepository, dataset_repo: DatasetRepository)
- Method: analyze_downstream_impact(dataset_id: str, field_name: str, max_depth: int = 5) -> dict:
  1. Look up dataset name from dataset_repo.get_dataset_name(dataset_id)
  2. Call lineage_repo.get_downstream_lineage(dataset_name, field_name, max_depth)
  3. Build impacted assets list with deduplication (use target_dataset.target_field as key)
  4. For each unique target, parse database_name and table_name from target_dataset (split on ".")
  5. Determine impactType: "direct" if depth == 1, else "indirect"
  6. Calculate summary: totalImpacted, tableCount (unique tables), columnCount, byDatabase (count per db), byDepth (count per depth level), databaseCount (unique databases)
  7. Return:
     ```
     {
       "sourceAsset": {"datasetId": dataset_id, "datasetName": dataset_name, "fieldName": field_name},
       "impactedAssets": [
         {"databaseName": "...", "tableName": "...", "columnName": "...", "depth": N, "impactType": "direct"|"indirect"}
       ],
       "summary": {
         "totalImpacted": N,
         "tableCount": N,
         "columnCount": N,
         "databaseCount": N,
         "byDatabase": {"db_name": count, ...},
         "byDepth": {"1": count, "2": count, ...}
       }
     }
     ```
  - Note: maxDepth default of 5 matches the existing column lineage default. Research suggested 10 but we start conservative.
