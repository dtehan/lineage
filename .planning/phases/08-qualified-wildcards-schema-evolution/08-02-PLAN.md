**Test cases to implement:**

**QUAL-01: Basic qualified wildcard expansion**

1. `test_qualified_wildcard_single_table()` - `SELECT t1.* FROM table1 t1` with INSERT INTO target (a, b, c). Assert 3 lineage records mapping table1 columns to target columns by ordinal position. Assert confidence 0.70.

2. `test_qualified_wildcard_with_alias()` - `SELECT c.* FROM customers c` where alias 'c' maps to customers table. Assert columns resolve to actual table (customers), not the alias.

3. `test_qualified_wildcard_no_alias()` - `SELECT customers.* FROM customers` with table name (not alias) as qualifier. Assert expansion works with direct table name reference.

**QUAL-02: Multiple qualified wildcards**

4. `test_multiple_qualified_wildcards()` - `INSERT INTO target (a, b, c, d, e) SELECT t1.*, t2.* FROM table1 t1 JOIN table2 t2 ON t1.id = t2.id` where table1 has columns [col1, col2, col3] and table2 has [colA, colB]. Assert 5 lineage records: col1->a, col2->b, col3->c, colA->d, colB->e. This validates ordinal position matching across multiple qualified wildcards.

5. `test_qualified_wildcard_mixed_with_explicit()` - `SELECT t1.*, t2.name FROM table1 t1 JOIN table2 t2 ON t1.id = t2.id` where table1 has [col1, col2]. Assert lineage includes wildcard-expanded columns (confidence 0.70) AND explicit column (confidence 0.95).

6. `test_qualified_wildcard_ctas()` - `CREATE TABLE new_table AS (SELECT t1.* FROM table1 t1) WITH DATA`. Assert CTAS derives target column names from qualified wildcard source.

**QUAL-05: Graceful degradation**

7. `test_qualified_wildcard_unknown_alias()` - `SELECT unknown.* FROM table1 t1`. Assert returns empty list for the unknown alias wildcard (no crash). May fall back to pattern-based extraction.

8. `test_qualified_wildcard_no_resolver()` - `SELECT t1.* FROM table1 t1` with parser created WITHOUT resolver. Assert backward compatible (skips expansion, no error).

9. `test_qualified_wildcard_empty_columns()` - `SELECT t1.* FROM table1 t1` where resolver returns empty list for table1. Assert graceful skip (no crash).

**QUAL-06: Positional ORDER BY detection**

10. `test_positional_order_by_with_wildcard_warns()` - `INSERT INTO target SELECT * FROM source ORDER BY 1, 2`. Use a mock to capture logging output. Assert warning is logged. Lineage should still be extracted (warning, not failure).

11. `test_positional_order_by_without_wildcard_no_warn()` - `INSERT INTO target (a) SELECT col1 FROM source ORDER BY 1`. Assert no positional ORDER BY warning when no wildcards present (only warn when wildcards + positional ORDER BY combine).

**Implementation notes:**
